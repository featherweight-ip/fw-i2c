# Interface

Top-level module: `i2c_master_top`.

## Parameters

| Parameter | Width | Default | Description |
|---|---|---|---|
| `ARST_LVL` | 1 | `1'b0` | Active level of `arst_i`: with the default, `arst_i` is active low. (Later freecores commits change the default to `1'b1`; see {doc}`later-extension`.) |

That is the only parameter.

## Ports

### System and WISHBONE

| Port | Dir | Width | Description |
|---|---|---|---|
| `wb_clk_i` | in | 1 | The only clock. All logic, including bit timing, runs on it. |
| `wb_rst_i` | in | 1 | Synchronous reset, active high. |
| `arst_i` | in | 1 | Asynchronous reset. Its active level is set by `ARST_LVL`. Use one reset and tie the other off: `wb_rst_i = 0`, or `arst_i = ~ARST_LVL`. |
| `wb_adr_i` | in | 3 | Register address. |
| `wb_dat_i` | in | 8 | Write data. |
| `wb_dat_o` | out | 8 | Read data, registered. |
| `wb_we_i` | in | 1 | Write enable. |
| `wb_stb_i` | in | 1 | Strobe. |
| `wb_cyc_i` | in | 1 | Cycle. |
| `wb_ack_o` | out | 1 | Acknowledge, registered. |
| `wb_inta_o` | out | 1 | Interrupt request: registered `SR.IF & CTR.IEN`, active high, level. |

The core has no `wb_sel_i`, `wb_err_o`, `wb_rty_i` or stall signal.

### I2C pads

| Port | Dir | Description |
|---|---|---|
| `scl_pad_i` | in | SCL line as seen at the pad. Asynchronous: synchronized inside the core. |
| `scl_pad_o` | out | Constant `0`. |
| `scl_padoen_o` | out | Output enable, **active low**. `0` drives SCL low, `1` releases it. |
| `sda_pad_i` | in | SDA line as seen at the pad. |
| `sda_pad_o` | out | Constant `0`. |
| `sda_padoen_o` | out | Output enable, active low. |

The PDF names the enables `scl_pad_oe` and `sda_pad_oe`. The RTL names
them `*_padoen_o`. Tristate buffers go outside the core:

```verilog
assign scl = scl_padoen_o ? 1'bz : scl_pad_o;
assign sda = sda_padoen_o ? 1'bz : sda_pad_o;
assign scl_pad_i = scl;
assign sda_pad_i = sda;
```

On a single-wire bus model (simulation, or an FPGA without tristate
buffers), each line is the wired-AND of the enables:
`scl = &{scl_padoen_o, other_device_scl_oen, ...}`.

## WISHBONE timing

Each access takes two clocks. `wb_ack_o` is registered as
`wb_cyc_i & wb_stb_i & ~wb_ack_o`, so it is high in the second clock of
the access and low in the next one, even when the master keeps STB
asserted. Read data is registered in the same edge. A write takes effect
at the edge where `wb_we_i & wb_ack_o` is high.

```{wavedrom}
{ "signal": [
  { "name": "wb_clk_i", "wave": "p......." },
  { "name": "wb_cyc_i/stb_i", "wave": "01.0.1.0" },
  { "name": "wb_we_i",  "wave": "x1.x.0.x" },
  { "name": "wb_adr_i", "wave": "x=.x.=.x", "data": ["CR", "SR"] },
  { "name": "wb_dat_i", "wave": "x=.x....", "data": ["cmd"] },
  { "name": "wb_ack_o", "wave": "0.10..10" },
  { "name": "wb_dat_o", "wave": "x.....=x", "data": ["SR"] },
  { "name": "register", "wave": "x..=....", "data": ["CR=cmd"] }
],
  "head": { "text": "WISHBONE write then read (2 clocks per access)" }
}
```

Notes:

- `wb_dat_o` is updated on every clock from `wb_adr_i`, whether or not a
  cycle is active.
- `wb_ack_o` has no reset (see below).
- An access does not wait for anything. A CR write while a command is in
  progress overwrites the command.

## Clocking and reset

- There is a single clock domain. SCL is generated by dividing
  `wb_clk_i`. SCL and SDA inputs are synchronized with two flip-flops,
  then filtered.
- `arst_i` (asynchronously) and `wb_rst_i` (synchronously) reset all
  registers except these: `wb_ack_o`, `wb_dat_o`, and in the bit
  controller `dscl_oen` and `dout`. In a 4-state simulation, `wb_ack_o`
  stays X if `wb_cyc_i & wb_stb_i` is high at the first clock edge.
- Each RTL file includes `timescale.v` (`1ns/10ps`, inside
  `synopsys translate_off`), and most non-blocking assignments carry a
  `#1` delay. Verilator needs `--no-timing` (or `--timing`) to accept
  them, and `-I rtl/verilog` for the includes.
- Clearing `CTR.EN` does not reset the bit controller or stop it
  tracking the bus. See {doc}`deviations`.
